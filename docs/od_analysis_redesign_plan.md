# OD 分析重构方案

状态：Accepted

记录日期：2026-08-24

## 1. 问题定义

初版站点看板对所有起终站组合按累计次数取 Top 20。结果中大量路线为“同站出发、同站归还”，视觉上容易让读者误解为大多数行程没有跨站流动。

该现象不是严格的辛普森悖论。辛普森悖论要求分组趋势与总体趋势发生反转；本项目的问题是：

- OD 组合呈长尾分布。
- 同站行程集中在少数站点，每个自环组合次数较高。
- 跨站行程占绝大多数，但分散在大量 A→B 组合中。
- 固定 Top-N 只截取极小头部，无法代表总体结构。
- 当前 Sankey 将同站自环和跨站流向混在同一问题中。

项目将其定义为：**固定 Top-N 在长尾 OD 分布中的代表性失真**。

## 2. 已验证的诊断证据

以下数字来自当前 793,323 条展示样本，仅用于证明问题存在，不能作为最终全量结论：

| 指标 | 结果 |
|---|---:|
| 跨站行程占比 | 95.57% |
| 同站归还占比 | 4.43% |
| 按站名统计的跨站 OD 组合 | 209,043 |
| 当前全部 Top20 覆盖总样本 | 1.03% |
| 跨站 Top20 覆盖跨站行程 | 0.52% |
| 达到 80% 跨站流量所需站名 OD 对 | 89,934 |
| 同站行程中位时长 | 27.1 分钟 |
| 跨站行程中位时长 | 14.0 分钟 |

固定 Top20 适合展示“最强的若干连接”，不适合描述“整体流动主要是什么”。累计 80% 适合用作长尾指标，但 89,934 条线路无法放入 Sankey。

## 3. 当前实现的额外风险

### 3.1 非等概率样本

当前逻辑随机选择 80 个文件，再从每个文件读取前 10,000 行。不同批次可能包含 9 万至 40 多万行，因此每条行程的入样概率并不一致。该样本可用于开发看板，不能用于最终站点排名、净流量和比例结论。

### 3.2 站点身份跨期变化

样本中的 868 个站名里，806 个对应多个源站点 ID。主要原因可能是 TfL 新旧格式和编号体系变化。直接使用源 ID 会拆分同一物理站点；直接使用名称又可能错误合并同名站点。

在没有坐标和官方稳定映射前，本项目使用“规范化站名”作为候选规范站点键，同时保留所有源 ID、原始名称、有效时间和映射审计状态，不把该映射描述为完全准确的物理站点主数据。

## 4. 决策

### 4.1 先改数据层，不先美化旧 Sankey

对 242 个源批次进行全量流式聚合，不再使用 793,323 条展示样本生成最终 OD 指标。

生成以下公开聚合表：

| 表 | 粒度 | 用途 |
|---|---|---|
| `dim_station` | 一行一个候选规范站点 | 规范名称、别名、源 ID 数、有效时间、映射状态 |
| `station_alias` | 规范站点 × 源 ID × 原始名称 | 站点映射证据和人工复核入口 |
| `fact_od_flow` | 规范起点 × 规范终点 | 跨站/同站次数、平均时长、时长分层 |
| `fact_station_period` | 站点 × 日期类型 × 小时 | 流入、流出、净流量和调度分析 |
| `fact_same_station` | 站点 × 日期类型 × 小时 | 同站归还次数和时长结构 |

已确认不完整的 4 个源日期继续排除。原始观测层仍保留，不进行插值恢复。

### 4.2 分四层回答问题

| 层级 | 问题 | 指标 | 主要展示 |
|---|---|---|---|
| 总体结构 | 同站与跨站分别占多少？ | 行程数、占比、OD 对数量 | 100%堆叠条形图 |
| 长尾结构 | TopN能代表多少？ | Top10/20/50/100/500覆盖率、累计曲线 | Pareto 曲线和覆盖率表 |
| 跨站流向 | 哪些站点联系最强？ | 仅 `O≠D` 的路线次数 | 跨站 Sankey、单站流入流出 |
| 站点行为 | 哪些站点需要调度或偏向环骑？ | 流入、流出、净流量、同站率、时长 | 发散条形图、小时热力图、同站排名 |

### 4.3 同站归还不删除，单独研究

同站归还并不等于“没有移动”。用户可能完成环骑后回到原站。项目只根据现有字段做候选行为分层：

- 1-3 分钟：可能包含换车、误操作、测试或极短骑行。
- 3-15 分钟：短时往返。
- 15 分钟以上：较长环骑候选。

数据没有用户类型、路径、距离和骑行目的，因此不能把这些分层直接解释为确定行为原因。

## 5. 看板改造

原“站点与行程”页面拆为两个页签：

### 流向结构

- 跨站/同站占比和总量。
- OD 对数量与 Top20 覆盖率。
- 跨站 OD Pareto 累计曲线。
- 仅包含 `O≠D` 的 Top20 Sankey。
- Sankey 固定标注“当前图覆盖跨站流量 X%”。
- 支持 Top10/20/50 和单站视角，但不把 TopN 描述为总体结构。

### 站点诊断

- 站点流入、流出和净流量。
- 工作日/非工作日及小时筛选。
- 同站归还次数 Top10。
- 设置最低出发量门槛后的同站率 Top10。
- 同站与跨站时长分布对比。

## 6. 不采用的方案

- 不用“累计到 80% 的 OD 对”直接画 Sankey；数量过大。
- 不画完整 868×868 OD 热力图作为主图；密度过高。
- 不用对数线宽掩盖 TopN 代表性不足；对数缩放只解决视觉量级，不解决口径。
- 不使用当前数据不存在的距离、用户类型和骑行目的字段。
- 不把同站行程统一删除或统一判定为无效订单。

## 7. 验收标准

- 最终 OD 指标来自全量流式聚合，不来自等文件配额样本。
- 所有业务指标排除 4 个已确认不完整源日期。
- 跨站流向图不包含 `O=D`。
- 每张 TopN 图同时显示分母和覆盖率。
- 同站排名同时提供次数和站内比例，比例排名设置最低样本门槛。
- 站点别名和多 ID 映射可追溯，不静默合并。
- README 明确区分总体结构、头部案例和分析限制。
- 面试表述能够说明初版失败、验证证据、方案权衡和个人复核边界。

## 8. 实施顺序

1. 完成全量 OD 流式聚合和站点别名维表。
2. 生成同站/跨站、TopN覆盖率和长尾累计结果。
3. 将新表接入 DuckDB 和自动测试。
4. 重做两个站点分析页签。
5. 更新 README、分析案例和项目答辩材料。
